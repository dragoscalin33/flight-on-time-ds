Flight on Time

From Research Notebook (v5.0) to Production Pipeline (v6.0) — Brazilian Flight Delay Prediction

Before: Notebook v5.0
1 Single Notebook
One massive .ipynb file (~2000 lines). Data loading, cleaning, feature engineering, training, evaluation — all in one linear flow.
2 Hardcoded Everything
File paths, hyperparameters, thresholds, outlier rules — all scattered across cells as magic numbers. Change one thing = hunt through the whole notebook.
3 Load & Clean
Load 2.5M flight records. Drop duplicates, filter completed flights, parse datetimes, compute delay_minutes. Rules are inline — outlier thresholds (-60 to 1440 min) are magic numbers in cells.
4 Feature Engineering
Haversine distance, hour/day/month extraction, weather merge. Good features, but mixed with EDA plots and hard to reuse or modify independently.
5 Train CatBoost
Single 80/20 split. Manual hyperparameter tuning (depth, iterations, learning_rate by trial and error). No cross-validation — one "lucky" split can give misleading results.
6 Evaluate & Export
Print metrics to stdout (lost when notebook closes). Save model as .joblib. No version tracking — overwrite the file and lose the previous model forever.
7 No Serving
Notebook produces a .joblib file. The backend loads it manually. No API contract, no health checks, no batch predictions.
➔
After: Production v6.0
1 Configuration HYDRA
All settings in YAML: model params, data paths, outlier rules, feature lists, thresholds. Change anything from CLI: python -m src.models.train model.depth=8
2 Load & Clean (9 steps)
Drop duplicates → Remove leakage columns (visibility, justification codes) → Filter completed flights only → Coerce coordinates & weather to numeric → Parse 4 datetime columns → Drop rows missing scheduled/actual departure → Compute delay_minutes & duration_minutes → Remove outliers (delay > 24h or negative duration) → Build binary target (delay > 15 min).
3 Feature Engineering 12+ FEATURES
Geo: Haversine distance (km) from origin/dest coordinates
Temporal: departure hour, day of week, month
Calendar: Brazilian holiday flag (holidays lib)
Weather: precipitation (mm), wind speed (km/h)
Categorical: airline, origin airport, destination airport
4 Schema Validation PANDERA
Checks every column: correct dtype, value ranges (e.g. hour 0-23, month 1-12), no unexpected nulls. Catches bad data before training instead of mysterious failures later.
5 Stratified Split
80/20 train/test split preserving class balance (~30% delayed). Seed-controlled (42) for full reproducibility across runs.
6 Cross-Validation 5-FOLD CV
Stratified K-Fold on training set. Reports mean ± std for Recall, Precision, F1, F2, ROC-AUC per fold. Proves the model generalizes — not just one lucky split.
7 Train CatBoost NATIVE CAT
CatBoost with native categorical support (no OneHotEncoder needed for airline/airport). auto_class_weights='Balanced' handles the 70/30 imbalance. 500 iterations, depth 6, learning rate 0.1.
8 Threshold Optimization SAFETY-FIRST
F2-score sweep (0.20 → 0.80, 200 steps) finds mathematical optimum at 0.43. Business overrides to 0.35 — catches 90.8% of real delays. "Better to alert a passenger unnecessarily than let them miss a connection."
9 Evaluation & Artifacts
Confusion matrix, top-15 feature importance, threshold sensitivity curve. All saved as PNG + logged to MLflow for comparison across runs.
10 Export & Registry MLFLOW
Retrain on all data. Register in MLflow Model Registry with version tracking. Every run is logged, comparable, and reproducible.
